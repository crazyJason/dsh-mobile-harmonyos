## 0. 测试前置条件

### 0.1 设备与环境

| 项目 | 要求 |
| --- | --- |
| 手机 | 真实 HarmonyOS NEXT 设备（模拟器不能替代：ArkWeb、Asset Store、网络权限行为需真机） |
| 系统 | HarmonyOS NEXT 正式版；记录具体版本与 ArkWeb 版本 |
| 安装包 | 用 DevEco Studio 自动签名后的 HAP；未签名包无法安装 |
| 电脑 | 已安装 DeepSeek Harness 并启用 `dsh-mobile` 插件，移动访问已开启 |
| 网络 | 手机与电脑在同一 Wi-Fi（局域网场景）；远程场景另备自签名 FRP 或公网隧道入口 |
| 电脑端工具 | 能查看插件版本、设备列表、撤销设备、重新生成配对码；能看到网关日志 |
| 手机端工具 | `hdc`（抓日志）、录屏/截图工具 |

### 0.2 版本记录

每轮测试开始前记录以下版本，写入测试报告：

- 手机型号与 HarmonyOS 版本；
- ArkWeb 版本（系统应用信息或浏览器内核信息中可见）；
- DSH 版本；
- `dsh-mobile` 插件版本（电脑端插件页面或 `package.json`）；
- 本仓库构建信息（构建日期、git commit、是否签名）；
- 入口类型（局域网 / 自签名 FRP / 公网隧道）与端口。

### 0.3 每次用例前的准备

1. 用 `hdc install -r` 安装最新签名 HAP；
2. 在电脑端为每个“配对”用例**重新生成**配对链接（token 一次性，不能复用）；
3. 清空日志：`hdc shell hilog -r`；
4. 若用例涉及“已配对状态”，先确认 App 设备列表中的记录状态与预期一致。

| 级别 | 内容 | 状态 |

| L2 主流程 | 局域网配对、浏览、重启恢复 | ✅ 已执行（2026-11-24：配对、ArkWeb 浏览、重启恢复、电脑端设备列表通过） |

### TC-02 设备端协议自检（安装后的首个冒烟检查）

| 项 | 内容 |
| --- | --- |
| 前置 | TC-01 通过 |

## 3. 用例：局域网配对

### TC-04 局域网配对（粘贴 legacy 链接）

| 项 | 内容 |
| --- | --- |
| 前置 | 手机与电脑同一 Wi-Fi；插件已开启移动访问；App 无该电脑记录 |
| 步骤 | 1) 电脑端生成配对链接/二维码；2) 把完整链接复制到手机剪贴板（聊天工具发送后复制）；3) App「添加电脑」→「从剪贴板粘贴」；4) 确认 host/port（可再点「扫描局域网」选中同一台电脑）；5) 点击「开始配对」 |
| 预期 | 配对成功提示；列表出现该电脑，显示名称、`host:port`、局域网标签与可达状态；配对过程中不出现证书错误 |
| 证据 | 添加页与列表截图、电脑端设备列表新增记录、hilog（不得包含 token） |
| 备注 | 局域网入口的链接常见为 `#instance=<64hex>&token=<43char>`，也可能是 `dsh2` 自签入口；两种都应按本文预期成功 |

### TC-05 局域网配对（dsh2 自签链接）

| 项 | 内容 |
| --- | --- |
| 前置 | 电脑端使用自签 CA 入口（例如自签名 FRP 或非 discovery 模式），配对链接形如 `#key=dsh2.<64hex>.<43char>` |
| 步骤 | 同 TC-04 |
| 预期 | 成功；App 从 `/mobile-access/ca.cer` 下载 CA，校验证书指纹后固定；后续浏览无证书告警 |
| 证据 | 截图、hilog、电脑端插件日志中的 `ca.cer` 请求 |

### TC-06 局域网扫描发现

| 项 | 内容 |
| --- | --- |
| 前置 | 同一 Wi-Fi；电脑网关运行中 |
| 步骤 | 1) 进入「添加电脑」；2) 点「扫描局域网」；3) 观察结果列表 |
| 预期 | 数秒内列出运行中的电脑（`deviceName` + host:port）；同一台电脑只出现一次；点选后自动填入地址；若网络隔离/防火墙拦截，列表为空并给出“未发现电脑”提示 |

| 备注 | UDP 3443 与 mDNS 可能被路由器 AP 隔离/防火墙拦截；扫描失败不阻塞“粘贴链接”路径 |

## 5. 用例：远程与公网证书入口

### TC-16 公网证书入口（public-CA entry）

| 项 | 内容 |
| --- | --- |
| 前置 | 电脑端使用公网证书入口（Cloudflare/Cpolar/Tailscale/自有域名 + 有效公共证书），该入口不提供自签配对 CA；插件已生成配对码 |
| 步骤 | 方式 A：粘贴插件生成的完整链接（`#instance=...&token=...`）配对；方式 B：只粘贴 `dsh1.<64hex>.<43char>` 裸密钥，在「扫描局域网」选中该入口或手填 `host:port`，再点「开始配对」 |
| 预期 | `/mobile-access/ca.cer` 返回 404（或该入口无自签 CA）；App 使用**平台信任库**完成 TLS；配对成功；记录不保存固定 CA（`caPem` 为空）；浏览无证书告警。若裸密钥与所选电脑的 `instanceId` 不一致，应在配对前拒绝 |
| 证据 | 手机截图、hilog、电脑端 `ca.cer` 响应 |
| 备注 | 上游不会生成 `#key=dsh1...` 链接；不要用这种格式测试。公网证书入口可以用插件生成的 legacy 完整链接，或 `dsh1` 裸密钥 + 地址（后者正是为这条路径准备的输入方式）。 |

### TC-16B 裸密钥 + 公网地址配对

| 项 | 内容 |
| --- | --- |
| 前置 | 同 TC-16 方式 B；手机在移动网络下能访问该公网入口 |
| 步骤 | 1) 粘贴 `dsh1` 裸密钥；2) 手填公网域名（不带 `https://`，默认端口 3443，或显式写端口）；3) 配对 |
| 预期 | 解析为远程目标；`ca.cer` 404 → `pairWithSystemTrust()`；配对成功；设备记录标记为远程模式；后续浏览使用平台信任库 |
| 证据 | 截图、hilog、电脑端访问日志 |

### TC-17 自签名 FRP 远程入口（dsh2）

| 项 | 内容 |
| --- | --- |
| 前置 | 电脑端配置自签名 FRP/自有入口，证书为插件自签 CA，链接为 `dsh2` |
| 步骤 | 使用移动网络粘贴链接配对，然后浏览 |
| 预期 | CA 下载→指纹校验→固定→配对成功；浏览时 SSL 错误被证书链校验放行，页面可交互 |
| 证据 | 截图、hilog、电脑端日志 |
| 备注 | 没有此类入口时可跳过，并在报告中注明“环境不具备” |

### TC-18 地址变化（ADDRESS_CHANGED）

| 项 | 内容 |
| --- | --- |
| 前置 | 已配对局域网设备；电脑 IP 变化（DHCP 换地址）或入口域名解析变化 |
| 步骤 | 在 App 列表触发探活 |
| 预期 | 当前实现没有自动更新地址的流程：记录显示不可达；用户需删除并重新配对（或手动修改地址功能若后续加入）。测试时记录实际行为，不要假定会自愈 |
| 证据 | 截图、电脑端新地址 |

### TC-18B 远程降级保护（当前未接线，作为回归基线）

| 项 | 内容 |
| --- | --- |
| 前置 | 已用 `dsh2` 链接配对过一台**远程**电脑，记录里保存了固定 CA；准备该入口的**不要求 CA** 的密钥（`dsh1` 裸密钥 + 地址，或该入口的 legacy 完整链接），且该入口的 `/mobile-access/ca.cer` 返回 404 |
| 步骤 | 1) 保留原远程记录；2) 用不要求 CA 的密钥对同一 `instanceId` 重新配对；3) 观察是否仍要求并提供 CA |
| 预期 | **协议要求**（PROTOCOL §3.3）：应仍强制 CA（`requiresCa` 置 true），`ca.cer` 404 即失败，绝不回退平台信任库。**当前实现**：`preserveRemotePin` 已实现但**未接入配对流程**（见 [ARCHITECTURE.md](ARCHITECTURE.md#15-已知缺口与后续工作)），实测可能回退系统信任库——如实记录实际行为，作为接线后的回归基线 |
| 证据 | 截图、hilog、电脑端 `ca.cer` 响应与 `native-pair` 访问日志 |
| 备注 | 接线后本用例的“预期”改为硬失败；若实测已表现为硬失败，说明接线已完成，请把本备注与 AGENTS.md 的“已知安全缺口”一行删掉 |

| 预期结果 | 对应本文用例的预期 |
| 发生时间 | 精确到分钟，便于对齐日志 |
| 日志 | `hdc shell hilog -T DshMobile` 的输出，**脱敏后**提供 |
| 电脑端证据 | 插件设备列表、网关日志中的对应请求（状态码） |

### 9.1 必须先脱敏的内容

- 配对链接的 fragment（包含一次性 token）；
- `deviceToken`、`sessionToken`、`csrfToken` 的完整值（保留前 2–4 位与长度即可）；
- 公网域名/IP（如涉及隐私，用 `x.x.x.x`/`example.com` 替代）；
- 用户数据、会话内容、文件路径；
- 签名材料：`*.p7b`、`*.p12`、`*.cer`、`*.pem` 及其密码，**永远不要**附在缺陷里。

### 9.2 日志抓取

```powershell
# 清空旧日志
& 'D:\Programs\Huawei\DevEcoStudio\sdk\default\openharmony\toolchains\hdc.exe' shell hilog -r

# 只抓本项目（tag = DshMobile，domain = 0x0D5B）
& 'D:\Programs\Huawei\DevEcoStudio\sdk\default\openharmony\toolchains\hdc.exe' shell hilog -T DshMobile -x
```

> `-x`（非阻塞读，打印完缓冲区即退出）**必须带**。不带 `-x` 时 `hilog -T DshMobile` 会一直流式输出不退出，
> 在脚本或 CI 里会把命令挂死；要实时看日志再手动去掉 `-x`。
>
> 另外：日志 domain 必须是 `0x0D5B`。用 `0x0000` 打日志在 HarmonyOS 7 上**看不到**（第一轮真机踩过，
> 见 [§11.3](#113-本轮缺陷已修复) D-04），所以 ability 层也必须走 `common/Log.ets` 而不是直接调 `hilog`。

如需同时观察 ArkWeb/系统错误，可抓取全部日志后自行裁剪，但**提交前必须脱敏**。

| D-01 | 右上角「添加」按钮里的加号显示成一个白色小方块 | 源码用的是全角加号 `U+FF0B`，设备字体栈里没有该字形，回退渲染成小方块 | 改用 ASCII `+`，字号 20 → 24（`pages/Index.ets`） |
| D-02 | 底部导航条区域是一条**白条**，与深色界面割裂 | 该区域实际绘制的是**窗口背景**，只设 `setWindowSystemBarProperties({ navigationBarColor })` 不够（该调用本身成功、无报错） | `loadContent` 后补 `setWindowBackgroundColor('#0B0E14')`（`entryability/EntryAbility.ets`） |
| D-03 | 协议自检弹窗、toast 是浅色主题，浮在深色界面上很突兀 | 应用界面固定深色，但没有声明色彩模式，系统组件仍按设备主题（浅色）绘制 | `onCreate` 中 `setColorMode(COLOR_MODE_DARK)`（`entryability/EntryAbility.ets`） |
| D-04 | `hilog -T DshMobile` 一条应用日志都收不到 | ability 层直接调用 `hilog.info(0x0000, ...)`；domain `0x0000` 的日志在 HarmonyOS 7 上被丢弃，启动/窗口错误日志全部丢失（`system bar styling unavailable` 这类告警也看不到） | 改走 `common/Log.ets`（domain `0x0D5B` + 脱敏），并给 `Log` 增加 ability 层用法（`entryability/EntryAbility.ets`） |
| D-05 | **所有**局域网配对失败，提示「证书校验失败：网关证书与配对信息不一致」 | `X509Cert.getBasicConstraints()` 返回的是**路径长度**，HarmonyOS 对「CA:TRUE 且省略 pathLenConstraint」的证书返回 `-1`；代码把 `< 0` 当作“不是 CA”直接拒绝，而 `dsh-mobile` 生成的配对 CA 恰好没有该可选字段。真机日志：`pairing CA: basicConstraints=-1 … withinValidity=true` → `basic constraints do not allow the CA role` | 不再拿基本约束当门禁：保留「指纹 == instanceId + 有效期 + 自签名验签」，仅记录该值供排障（`protocol/CertPin.ets`，说明见 [ARCHITECTURE §9.2](ARCHITECTURE.md#92-bootstrap-链路)） |

**由此顺带补的可诊断性**：TLS 失败原先只折叠成一句用户提示，没有任何设备端日志。现在 `TlsHttp.ets` 会记录 socket 错误码，
`AppService.pair` 会记录「CA 是否取到 / 是否匹配 / 最终失败类别」，`CertPin.validatePairingCa` 会记录基本约束与有效期判定——
D-05 就是靠这三条日志在真机上一轮定位的。

复验方式（本轮已执行）：改完重新 `build.ps1` → `install.ps1` → `aa start` → 截图比对；D-04 复验后日志出现 `I A00D5B/…/DshMobile: EntryAbility onCreate`，D-05 复验后出现 `paired a DSH Mobile gateway`。

### 11.5 本轮新增的自动化测试手法（可复用）

真机用例不一定要手点，以下组合可以脚本化执行（本轮配对/浏览就是这么跑完的）：

| 能力 | 命令 |
| --- | --- |
| 截图取证 | `hdc shell snapshot_display -f /data/local/tmp/x.jpeg` + `hdc file recv` |
| 点击/长按/按键 | `hdc shell uitest uiInput click <x> <y>`、`longClick`、`keyEvent Back/Home` |
| 输入文本 | `hdc shell uitest uiInput inputText <x> <y> <text>` |
| 读控件树 | `hdc shell uitest dumpLayout -p /data/local/tmp/l.json` + `hdc file recv`（含 `text`/`bounds`，能精确定位坐标） |
| 启停应用 | `hdc shell aa start -a EntryAbility -b io.github.crazyjason.dshmobile.hmos`、`aa force-stop` |
| 抓日志 | `hdc shell hilog -T DshMobile -x`（必须带 `-x`，否则永久阻塞） |

两个坑：

- `uitest uiInput inputText` **单次最多注入约 120 字符**。配对链接（`https://…/pair#instance=…&token=…`，约 170 字符）一次填不进去，
  稳妥做法是改用 `dsh2.<64hex>.<43char>` 密钥（113 字符）+ 手动地址，这条路径本身也是受支持的配对入口。
- 点击前先 `dumpLayout` 拿真实 bounds。软键盘弹出会顶起布局，直接点固定坐标容易点空（本轮就点空过一次）。
