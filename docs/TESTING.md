## 0. 测试前置条件

### 0.1 设备与环境

| 项目 | 要求 |
| --- | --- |
| 手机 | 真实 HarmonyOS NEXT 设备（模拟器不能替代：ArkWeb、Asset Store、网络权限行为需真机） |
| 系统 | HarmonyOS NEXT 正式版；记录具体版本与 ArkWeb 版本 |
| 安装包 | 用 DevEco Studio 自动签名后的 HAP；未签名包无法安装 |
| 电脑 | 已安装 DeepSeek Harness 并启用 `dsh-mobile` 插件，移动访问已开启 |
| 网络 | 手机与电脑在同一 Wi-Fi（局域网场景）；远程场景另备自签名 FRP 或公网隧道入口 |
| 电脑端工具 | 能查看插件版本、设备列表、撤销设备、重新生成配对码；能看到网关日志 |
| 手机端工具 | `hdc`（抓日志）、录屏/截图工具 |

### 0.2 版本记录

每轮测试开始前记录以下版本，写入测试报告：

- 手机型号与 HarmonyOS 版本；
- ArkWeb 版本（系统应用信息或浏览器内核信息中可见）；
- DSH 版本；
- `dsh-mobile` 插件版本（电脑端插件页面或 `package.json`）；
- 本仓库构建信息（构建日期、git commit、是否签名）；
- 入口类型（局域网 / 自签名 FRP / 公网隧道）与端口。

### 0.3 每次用例前的准备

1. 用 `hdc install -r` 安装最新签名 HAP；
2. 在电脑端为每个“配对”用例**重新生成**配对链接（token 一次性，不能复用）；
3. 清空日志：`hdc shell hilog -r`；
4. 若用例涉及“已配对状态”，先确认 App 设备列表中的记录状态与预期一致。

## 1. 测试分级与执行顺序

| 级别 | 内容 | 状态 |
| --- | --- | --- |
| L0 构建 | 命令行构建出 HAP | ✅ 已执行（仅编译，无真机） |
| L1 基础可用性 | 安装、启动、空列表、**协议自检（首个冒烟检查）** | ⛔ 未执行 |

| L3 失败路径 | 错误 token、过期、撤销、限流、证书错误 | ⛔ 未执行 |

建议按 L1 → L2 → L3 → L4 的顺序执行；L5 依赖额外的电脑端入口配置，可单独安排。

> **L1 的第一步固定为：安装/启动后先运行「运行协议自检」，期望全部通过。** 自检失败说明安装的构建与协议规则不一致，应先停下修构建，不要继续配对用例。

## 3. 用例：局域网配对

### TC-04 局域网配对（粘贴 legacy 链接）

## 5. 用例：远程与公网证书入口

### TC-16 公网证书入口（public-CA entry）

| 项 | 内容 |
| --- | --- |
| 前置 | 电脑端使用公网证书入口（Cloudflare/Cpolar/Tailscale/自有域名 + 有效公共证书），该入口不提供自签配对 CA；插件已生成配对码 |
| 步骤 | 方式 A：粘贴插件生成的完整链接（`#instance=...&token=...`）配对；方式 B：只粘贴 `dsh1.<64hex>.<43char>` 裸密钥，在「扫描局域网」选中该入口或手填 `host:port`，再点「开始配对」 |
| 预期 | `/mobile-access/ca.cer` 返回 404（或该入口无自签 CA）；App 使用**平台信任库**完成 TLS；配对成功；记录不保存固定 CA（`caPem` 为空）；浏览无证书告警。若裸密钥与所选电脑的 `instanceId` 不一致，应在配对前拒绝 |
| 证据 | 手机截图、hilog、电脑端 `ca.cer` 响应 |
| 备注 | 上游不会生成 `#key=dsh1...` 链接；不要用这种格式测试。公网证书入口可以用插件生成的 legacy 完整链接，或 `dsh1` 裸密钥 + 地址（后者正是为这条路径准备的输入方式）。 |

### TC-16B 裸密钥 + 公网地址配对

| 项 | 内容 |
| --- | --- |
| 前置 | 同 TC-16 方式 B；手机在移动网络下能访问该公网入口 |
| 步骤 | 1) 粘贴 `dsh1` 裸密钥；2) 手填公网域名（不带 `https://`，默认端口 3443，或显式写端口）；3) 配对 |
| 预期 | 解析为远程目标；`ca.cer` 404 → `pairWithSystemTrust()`；配对成功；设备记录标记为远程模式；后续浏览使用平台信任库 |
| 证据 | 截图、hilog、电脑端访问日志 |

### TC-18 地址变化（ADDRESS_CHANGED）

### TC-18B 远程降级保护（当前未接线，作为回归基线）

| 项 | 内容 |
| --- | --- |
| 前置 | 已用 `dsh2` 链接配对过一台**远程**电脑，记录里保存了固定 CA；准备该入口的**不要求 CA** 的密钥（`dsh1` 裸密钥 + 地址，或该入口的 legacy 完整链接），且该入口的 `/mobile-access/ca.cer` 返回 404 |
| 步骤 | 1) 保留原远程记录；2) 用不要求 CA 的密钥对同一 `instanceId` 重新配对；3) 观察是否仍要求并提供 CA |
| 预期 | **协议要求**（PROTOCOL §3.3）：应仍强制 CA（`requiresCa` 置 true），`ca.cer` 404 即失败，绝不回退平台信任库。**当前实现**：`preserveRemotePin` 已实现但**未接入配对流程**（见 [ARCHITECTURE.md](ARCHITECTURE.md#15-已知缺口与后续工作)），实测可能回退系统信任库——如实记录实际行为，作为接线后的回归基线 |
| 证据 | 截图、hilog、电脑端 `ca.cer` 响应与 `native-pair` 访问日志 |
| 备注 | 接线后本用例的“预期”改为硬失败；若实测已表现为硬失败，说明接线已完成，请把本备注与 AGENTS.md 的“已知安全缺口”一行删掉 |

## 6. 用例：浏览与证书

| 预期 | 先显示“正在建立安全连接…”，随后加载 DSH 移动端页面；页面可滚动与交互；不出现登录页（会话 Cookie 生效）；顶部栏显示标题与 host:port；返回键回到列表 |

| 备注 | 页面交互能力取决于上游 DSH 移动端在浏览器模式下的支持程度 |

### TC-20 自签证书的 SSL 续接

| 项 | 内容 |
| --- | --- |
| 前置 | 配对的是自签 CA 入口（无公共证书） |
| 步骤 | 打开设备，观察首屏与资源加载；在页面内进行跳转 |
| 预期 | 页面正常加载，不出现证书拦截页/白屏；hilog 无“证书与配对信息不一致”；页面内同源跳转不触发证书错误 |
| 证据 | 录屏、hilog |

### TC-20B 局域网入口不提供 `ca.cer` 时必须判为身份不匹配

| 项 | 内容 |
| --- | --- |
| 前置 | 一台局域网电脑，其移动访问网关**不提供** `/mobile-access/ca.cer`（例如临时用自建桩服务只回答 404，或改配置使 `pairingCaFile` 缺失）；配对链接使用 legacy 片段或 `dsh2` |
| 步骤 | 1) 扫描/手填该地址；2) 粘贴配对链接或裸密钥；3) 点击“开始配对” |
| 预期 | 在发送配对令牌**之前**失败，提示“证书校验失败：网关证书与配对信息不一致”（`AuthFailureKind.TLS`），**不得**回退到系统信任库、不得发出 `native-pair` 请求 |
| 证据 | 截图、hilog（应能看到 `gateway did not serve the pairing CA`）、桩服务访问日志（不应出现 `POST /mobile-access/auth/native-pair`） |
| 备注 | 对应 ADR-0002 规则 3/4，与上游 `PairingTrust.selectTrustAnchor` 的 LAN 行为一致；仅公网证书远程入口允许 404 → 系统信任库 |

### TC-21 证书不匹配（负向）

| 项 | 内容 |
| --- | --- |
| 前置 | 已配对电脑 A；准备另一台电脑 B，其 `instanceId` 与 A 不同，但让手机访问 B 的地址（改 hosts/DNS 或反向代理；仅测试环境） |
| 步骤 | 1) 保持 A 的记录；2) 让 A 的 origin 解析到 B；3) 打开设备 |
| 预期 | TLS 握手失败或 Web 证书校验失败，App 提示“证书校验失败/网关证书与配对信息不一致”，**不**加载页面、不把 Cookie 发送给 B |
| 证据 | 截图、hilog、B 端访问日志（应看不到 Cookie） |
| 备注 | 属于安全测试，禁止在生产网络或他人设备上进行 |

### TC-22 会话过期后续期

| 项 | 内容 |
| --- | --- |
| 前置 | 已配对；能观察会话到期（可等待 `sessionExpiresAt`，或由电脑端使会话失效） |
| 步骤 | 1) 保持浏览页挂起（应用在前台）；2) 等待超过会话有效期 / 触发一次后台续期；3) 继续操作页面 |
| 预期 | 10 分钟定时续期成功则页面继续可用；若续期失败，下次进入浏览页会重新续期；设备凭据未过期时不需要重新配对 |
| 证据 | hilog、截图、电脑端会话日志 |

### TC-23 删除本地记录后的 Cookie 残留检查

| 项 | 内容 |
| --- | --- |
| 前置 | 已配对并浏览过 |
| 步骤 | 1) 长按设备卡 → 删除本地记录；2) 重新配对同一台电脑；3) 观察浏览是否正常 |
| 预期 | 删除本地记录不影响电脑端授权；重新配对成功并可浏览。**观察项**：当前实现删除记录时未主动清除 ArkWeb 中已注入的会话 Cookie，若旧 Cookie 仍被复用，页面可能在新会话建立前短暂可用或失效；记录实际行为 |
| 证据 | 截图、hilog |
| 备注 | 这是当前实现的已知观察点，不影响安全边界（Cookie 仍是 host-only/HTTPS，且由同一台电脑签发） |

## 9. 缺陷报告需要采集的信息

一个可处理的缺陷报告应包含：

| 字段 | 说明 |
| --- | --- |
| 用例编号 | 例如 TC-04、TC-21 |
| 严重级别 | 阻断 / 严重 / 一般 / 轻微 |
| 手机型号 | 完整型号（如 `Pura 70 Pro`） |
| HarmonyOS 版本 | 设置 → 关于手机 → 版本号（示例：`HarmonyOS NEXT x.y.z`） |
| ArkWeb 版本 | 系统应用信息或浏览器内核信息中的版本号 |
| DSH 版本 | 电脑端 DeepSeek Harness 版本 |
| dsh-mobile 插件版本 | 电脑端插件版本（与 `metadata.pluginVersion` 对照） |
| 本仓库构建 | git commit、构建日期、是否签名、构建命令来源 |
| 入口模式 | 局域网 / 自签名 FRP / 公网隧道 / 反向代理 |
| 网络拓扑 | 手机网络、电脑网络、是否有 AP 隔离/代理/VPN |
| 复现步骤 | 逐步操作，含输入类型（不要贴真实 token） |
| 实际结果 | 现象、错误文案、截图/录屏 |
| 预期结果 | 对应本文用例的预期 |
| 发生时间 | 精确到分钟，便于对齐日志 |
| 日志 | `hdc shell hilog -T DshMobile` 的输出，**脱敏后**提供 |
| 电脑端证据 | 插件设备列表、网关日志中的对应请求（状态码） |

### 9.1 必须先脱敏的内容

- 配对链接的 fragment（包含一次性 token）；
- `deviceToken`、`sessionToken`、`csrfToken` 的完整值（保留前 2–4 位与长度即可）；
- 公网域名/IP（如涉及隐私，用 `x.x.x.x`/`example.com` 替代）；
- 用户数据、会话内容、文件路径；
- 签名材料：`*.p7b`、`*.p12`、`*.cer`、`*.pem` 及其密码，**永远不要**附在缺陷里。

### 9.2 日志抓取

```powershell
# 清空旧日志
& 'D:\Programs\Huawei\DevEcoStudio\sdk\default\openharmony\toolchains\hdc.exe' shell hilog -r

# 只抓本项目（tag = DshMobile，domain = 0x0D5B）
& 'D:\Programs\Huawei\DevEcoStudio\sdk\default\openharmony\toolchains\hdc.exe' shell hilog -T DshMobile
```

如需同时观察 ArkWeb/系统错误，可抓取全部日志后自行裁剪，但**提交前必须脱敏**。
